# 📝 app.py を読み解く

## このファイルは何者か

`app.py`は、このAIライティングツールの**ホームページ**です。Streamlitというライブラリを使って書かれた、Pythonだけで動くWebアプリのエントリーポイント（最初に読み込まれるファイル）です。

やっていることは大きく3つだけです。

1. ページの見た目設定
2. 共通サイドバーの表示
3. 7つの機能ページへのリンク一覧をカード形式で並べる

順番に見ていきましょう。

---

## ① ページ設定：アプリの"表札"を出す

```python
import streamlit as st

from utils.sidebar import render_common_sidebar

st.set_page_config(
    page_title="AIライティングツール",
    page_icon="✍️",
    layout="wide",
)
```

`st.set_page_config()`は、ブラウザのタブに表示されるタイトル（`AIライティングツール`）とアイコン（✍️）、そして画面の使い方（`layout="wide"`＝横幅いっぱいに広げる）を決めています。

Streamlitのお約束として、これは**ファイルの一番最初の`st.〜`呼び出し**である必要があります。他の`st`コマンドより先に書かないとエラーになります。

---

## ② 共通サイドバーの呼び出し

```python
render_common_sidebar()
```

たった1行ですが、ここが地味に重要です。中身は`utils/sidebar.py`にあり、以下を表示しています。

- Gemini APIキーの入力欄
- 使用するモデル（`gemini-3.6-flash`など）の選択セレクトボックス
- APIキーが設定済みかどうかの✅/⚠️表示

このサイドバーは`app.py`だけでなく、`pages/`の中の7つのページ全部で同じ関数を呼んで表示しています。つまり「共通ヘッダー」ならぬ「共通サイドバー」を1箇所にまとめておくことで、修正がある時に1ファイルだけ直せば全ページに反映される、という設計になっています。

## ③ タイトルと説明文

```python
st.title("✍️ AIライティングツール")
st.caption("Gemini APIを使った個人用ライティング支援アプリ")

st.markdown(
    """
左のサイドバーからページを選んで使い始めてください。
初回はサイドバーで **Gemini APIキー** を入力するか、`.env` に `GEMINI_API_KEY` を設定してください。

```

ここは素直に大見出し・キャプション・Markdown本文を表示しているだけです。`st.markdown`の中では`**太字**`のようなMarkdown記法がそのままレンダリングされます。

## ④ 機能一覧をデータとして持つ

ここがこのファイルで一番"エンジニアらしい"部分です。

```python
features = [
    ("📝", "ブログ記事作成", "pages/1_📝_ブログ記事作成.py", "テーマや要点からブログ記事の下書きを生成します。"),
    ("📧", "メール返信作成", "pages/2_📧_メール返信作成.py", "受信メールの内容とトーンを指定して返信文を作成します。"),
    # ...以下5つ続く
]
```

7つの機能を、**タプルのリスト**として1箇所にまとめています。それぞれのタプルは `(アイコン, タイトル, ページのファイルパス, 説明文)` の4要素です。

こう「データ」として持っておくメリットは、下のループ処理がとてもシンプルになることです。もし機能一覧を4つのタプルではなく、1つずつ`if`文で分岐して書いていたら、コードはもっと長く、新しい機能を追加するたびに書き換える箇所が増えていたはずです。

---

## ⑤ カードを2列で並べて表示する

```python
cols = st.columns(2)
for i, (icon, title, page, desc) in enumerate(features):
    with cols[i % 2]:
        with st.container(border=True):
            st.markdown(f"### {icon} {title}")
            st.write(desc)
            st.page_link(page, label=f"{title}を開く", icon=icon)
```

ここを分解すると：

- **`st.columns(2)`** — 画面を左右2つのカラム（列）に分割します。`cols`には`[左カラム, 右カラム]`が入ります。
- **`enumerate(features)`** — さっきのリストを、インデックス番号`i`付きで1つずつ取り出します。
- **`cols[i % 2]`** — ここがポイント。`i % 2`は「iを2で割った余り」なので、`0, 1, 0, 1, 0, 1, 0`と交互になります。つまり**0番目のカードは左列、1番目は右列、2番目はまた左列…**と、ジグザグに配置されるわけです。7個の機能があるので、最終的に4行×2列（最後の1個だけ左に余る）のレイアウトになります。
- **`st.container(border=True)`** — 枠線付きの箱を作り、その中にタイトル・説明・リンクボタンを入れることで、カードっぽい見た目にしています。
- **`st.page_link(page, ...)`** — クリックすると`pages/`配下の該当ファイルに画面遷移するリンクボタンです。

## まとめ：app.pyの役割は「玄関」

`app.py`自体は、AIを呼び出す処理は一切していません。プロンプトの組み立てもGemini APIへのリクエストも、すべて`pages/`配下の各ページと`utils/gemini_client.py`が担当しています。

`app.py`の仕事は、あくまで

- 共通の設定・サイドバーを最初に呼ぶ
- 7つの機能への"入り口"を、見やすいカード一覧として案内する

という「アプリの玄関・ナビゲーション」に徹している、というのがこのファイルの設計思想です。新しい機能ページを追加する時も、`pages/`に新しいファイルを置いて、この`features`リストに1行タプルを追加するだけで済むようになっています。
